# 无限易R-Breaker模拟盘适配

2026-10-26。独立适配当前历史手续费＋ATR20/1%风险＋对锁节点。新增代码在`infinitrader_adapter`、`platform_strategies`及打包/诊断脚本；原`backtest`代码、节点配置、历史结果和封存不改。此适配仅面向中金所IF/IH/IC/IM模拟盘，不是通用实盘网关。

## 已确认的实时资金口径

用户确认：保持原策略判断，额外加入无限易柜台风险度，两个检查均允许才增加方向。柜台阈值同为90%，解锁不豁免。

用户随后明确：实际模拟账号已指定，手续费/保证金参数按回测来源估算，不再要求逐合约柜台确认费率；实际保证金约束通过柜台账户整体风险度判断，并比较估算是否准确。本条优先于早先“缺少单合约柜台费率则不交易”的评估。

1. 原策略层继续使用当前权益1%风险预算、ATR20×1、净50%与估算大边总90%，不恢复5%逐分钟分批。
2. 实时层读取指定账号动态权益、保证金、冻结保证金、可用资金、风险度及累计手续费。新增方向的新开和解锁都要求柜台风险度低于90%，预计委托占用后仍满足上限和可用资金。
3. 保护性对锁是真实开仓，同样受柜台开仓检查约束。柜台可能先冻结新腿全部保证金，再给予大边抵扣，所以预留不提前使用尚未实现的抵扣。普通减仓平仓仍允许，但先检查同合约同方向当日计费余额。
4. 15%为原研究保证金假设，不能称为已核实交易所保证金率。双门槛不保证未来始终低于100%，价格变化、柜台缓存、拒单与成交延迟仍可能造成差异；被动超限照实记录，不新增自动强平或付平今费退出。

## 参数来源与柜台接口

账户接口使用本机已核对的`get_account_fund_data`；双向持仓通过`pythongo.infini.get_investor_position(..., simple=True)`读取，合约通过`get_instruments_by_product`及`get_instrument_data`读取。当前SDK的合约列表返回按ProductClass分组的字典，非平铺列表，代码按本机结构处理。

本机`AccountData.risk`是柜台返回的`margin / dynamic_rights`，单位为比例，90%写作0.90。此SDK未暴露独立柜台Risk原始字段，也未发现逐合约费率/保证金率查询；不能编造查询接口。

默认`rules_mode=checkpoint_estimates`：打包时从当前节点固定历史费用版本`bf211dd35fc143b6a7d62bf4a483aa98`及as_of导出估算数据。实际合约有记录则沿用该记录；新增合约无记录时按同品种节点最后主力的费用作显式估计，来源合约写入配置。保证金沿用节点15%。这不是声称历史数据已经覆盖未来日期。真实累计手续费、占用保证金及风险度仍实时查询，预计费用不另扣柜台现金。

原节点的风险定仓/止损预计成本公式保持，实际订单预算另参考上述费用估计。实际单笔TradeData没有手续费字段，因此风险簿费用为带来源的估计，账户费用以柜台累计数为准，不能把估算字段当实际逐笔佣金。

可选`rules_mode=counter_confirmed`保留未来人工核实参数入口，所有费率/按手费用/多空保证金率/来源/有效期均须显式填写，缺失不回退默认值。该模式不是当前启用前提。

接口依据：[BaseStrategy](https://infinitrader.quantdo.com.cn/pythongo_v2/modules/pythongo_base)、[AccountData](https://infinitrader.quantdo.com.cn/pythongo_v2/modules/pythongo_classdef/account)、[回报数值映射](https://infinitrader.quantdo.com.cn/pythongo_v2/faq/mapping)、[柜台资金说明](https://infinitrader.quantdo.com.cn/docs/quick_start/b4_fund.html)。本机SDK源码静态核对结果另存`sdk_inspection.json`。

## 行情与执行

- 四品种由一个组合实例协调，使用指定独立模拟账号。主力按前一交易日持仓量选择，平局按成交量和代码；实际合约此前20日简单TR均值计算ATR，不用主连复权ATR。历史数据通过PythonGO MarketCenter D1获取，并排除当前未完成日。
- 第一次启动应在09:25前，并保持账号初始无外来持仓/活动订单。交易日取TickData.trading_day，不按自然日推断。已有完整事件日志的次日可保留跨日持仓；启动遇未知持仓、未恢复订单或超过允许范围的盘中行情空档则停止新增执行，不能虚构恢复过程。
- 09:30开盘价来自真实行情open_price，生成独立开盘结果观察；不生成虚拟竞价成交。旧主力在竞价前提交目标，但只有实际合约状态允许、报价有效、委托获接受且真实成交回报到达才算完成。
- 自建薄分钟时钟只合成真实Tick的完整分钟，休市不造Bar，不前值填充缺失分钟。第一笔连续快照建立累计量基线，避免将无法拆分的竞价量全算到首根分钟；该基线可能保守漏计首笔量，后续比较应单列。
- 仍在分钟结束后判断信号与止损。实时成交可能在分钟中途：风险观察只使用实际取得敞口后的报价，避免分钟内入场前极值造成伪止损；即使提前观察到触价，也等分钟结束才发退出意图。切片行情与秒级成交时间不构成Tick级路径保证。
- 14:59隔夜判断不等到15:00完整行情，午休及最后一分钟由本实例定时器处理。缺失完整主力分钟、过旧报价、乱序或未来时间戳不猜测补齐。
- 报单使用已知对手价再超1tick的限价，服从涨跌停和交易状态。不是承诺按回测开盘价加1tick成交。
- 下一分钟总成交量在实时报单时未知，实时版本用“上一完整分钟已观察量×10%”限制本分钟发单量，单个目标剩余继续后续分钟处理。初次启动无上一分钟量时会延后方向入场；不能把它描述为精确复刻回测参与率。竞价前旧主力清理也不绕过可执行的量和资金限制，可能延后到连续交易。

这些均为实时执行差异，不修改或覆盖研究节点。估算、实际成交和柜台资金分别记录，不能要求实时PnL逐笔复现历史回测。

## 订单与恢复

使用`make_order_req`明确开平：买/卖方向及开/平标志分别设置，不调用平台“平今优先”的自动平仓函数。所有平仓包括解锁先查同合约同方向当日计费余额，不安全则真实反向开仓；保护性反向仓不作为新的反转信号交易。

每笔订单固定action、logical_side、group、价格、数量和唯一memo，真实成交按该冻结映射解释，不读取已经变化的最新目标路由。部分成交、撤单中成交、报单回报先于成交回报、重复回报均单独处理。一次仅一个在途订单，柜台持仓、费用更新和冻结资金对齐前不申请下一笔，减少账户缓存与多品种并发占用风险。

新目标取消旧目标时等待真实撤单确认；发送撤单成功不是撤单完成。完整成交才改变实物持仓和净敞口，不运行Engine制造模拟Fill；也不运行第二套现金结算。账户由柜台权威维护，本地只有成交归属及风险簿。

事件日志逐条fsync并作SHA256链校验，发单前先持久化意图；源代码或关键配置变化、断尾、日志损坏会阻止盲目恢复。重启回放真实事件重建冻结风险、当日余额和目标。尚有未知未完成订单时，须接收/核对订单终态与完整成交，并与柜台库存对齐，不能自行清零。暂停时申请撤销未成交委托，保留持仓并继续接收晚到回报，不自动平仓。

实际SDK资金快照未提供明确柜台生成时间。适配记录查询时刻、等待已成交费用反映并留出刷新间隔，不声称这些措施能证明柜台数据实时无延迟。故障、拒单及无法对锁均照实保留，需在客户端核对；不将未完成退出写成已止损。

## 打包、安装与运行

项目虚拟环境用于开发验证，平台使用其配置好的Python3.12环境及PythonGO依赖；另需numpy和tzdata。本机检测到的独立Python3.12环境已有pydantic、apscheduler、numpy、tzdata、PyQt5，但不据此推断无限易已经选择了该解释器。

```powershell
.venv\Scripts\python.exe -m scripts.package_infinitrader_adapter --inspect-platform "<无限易模拟版目录>"
.venv\Scripts\python.exe -m scripts.package_infinitrader_adapter --output outputs/infinitrader_adapter_20261026/bundle --investor "<指定模拟账号>" --mode simulation
.venv\Scripts\python.exe -m scripts.package_infinitrader_adapter --install-platform "<无限易模拟版目录>" --investor "<指定模拟账号>" --mode simulation
```

安装仅新增`pyStrategy/rbreaker_adapter_20261026`与`pyStrategy/self_strategy/RBreakerSimulation.py`及同名.runtime.json。不覆盖PythonGO或已有用户策略，不启动策略，不登录或发送订单；若同名部署已存在则拒绝覆盖。

在无限易模拟客户端中核对登录的模拟账号，在“量化－PythonGO”加载`RBreakerSimulation.py`、创建一个实例、确认配置文件，然后在盘前启动。交易所/实际合约由程序发现，不需人工把主连代码填成交易合约。`mode=observe`仅记录、`mode=simulation`允许本适配发送真实模拟委托；只有用户运行实例后才启用。

安装目录下`configuration/simulation.json`已写入指定账号及90%柜台上限；`checkpoint_estimates.json`保存估算来源。不得同时运行两个实例或另一份同账号策略；状态目录有进程锁，但不同复制目录之间仍需用户保证账号独占。

## 判断15%估算准不准

`configuration/state/counter_account.jsonl`记录柜台动态权益、实际保证金、冻结资金、风险度、可用资金、累计手续费及估算比较。只在实物持仓已同步、报价新鲜、估算完整且非空仓时纳入可用比较。

- 保证金偏差 = 柜台实际占用 − 原15%大边估算。
- 实际/估算比值为1表示该观察接近；1.2表示柜台实际比估计高20%。
- 折算统一保证金率 = 15%×实际/估算比值，仅用于诊断，不宣称这是每个合约的实际费率。
- 柜台冻结金额单列，不拿持仓估算与“占用＋冻结”混作同一口径。

```powershell
.venv\Scripts\python.exe -m scripts.summarize_infinitrader_paper --state "<部署目录>/configuration/state" --output outputs/infinitrader_paper_report
```

汇总给出比值中位数、平均/最大绝对相对偏差及落在±10%内的观察比例。没有真实柜台观察时明确输出“不能判断”，不拿合成测试或历史假设冒充模拟结果。

每日`daily_日期.json`是15:15之后最后一次柜台观测，非官方结算单。day_pnl使用柜台动态权益减上日余额并调整当日出入金，费用以柜台累计数记录；次日仍须对结算单核对，不能重复划转期货结算盈亏。

## 验证边界

新增测试使用明确标记的假柜台回调，覆盖双门槛、解锁、全腿冻结、部分成交/撤单竞态、恢复、费用时点、分钟止损及四品种端到端观察/模拟路径；不是已连接无限易实际模拟站点。原节点另存完整重跑并核对，现金流水同一结算时刻的行顺序可能不同，按完整行内容及独立账务审计判断，不隐藏差异。

实际启动后仍需验收主力日线响应字段与时点、竞价/分钟生成、真实双向开平、柜台计费与保证金、断线恢复和实际结算。当前源码与测试通过不等于模拟盘或实盘已验收。
