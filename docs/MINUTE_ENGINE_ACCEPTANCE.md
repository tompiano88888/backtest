# 分钟回测层验收范围

2026-10-20用户明确：所有策略不必加入框架，本阶段主要验收框架的回测层。策略是外部回调/指令来源和测试负载，不以某策略的盈利、内置或迁移完成作为框架验收条件。

核心依赖为标准事件/行情、只读账户观察、下单接口、统一Engine撮合与Ledger账务；不依赖R-Breaker、套利或其他策略实现。已有研究模块及结果继续保留，物理目录整理不是本次验收前置条件。

## 集合竞价的确认与实现

用户确认股指期货09:30记录是集合竞价结果、对应日线开盘价，可按该价格零滑点成交。

- `models.Auction(instrument,time,trading_date,price,volume,...)`表示离散竞价结果；不伪造09:29—09:30普通Bar，也不把09:31连续交易Bar当作竞价。
- `Frame.auctions`承载当前时点结果。仅在该时点之前提交的有效指令可参与；撮合先执行，回调随后看到`ctx.auctions`。看到结果后提交的新指令不能倒填竞价成交。
- 显式竞价事件成交价为price、零滑点。配置的费用、量参与率、开平/可平数量、停牌和涨跌停等真实约束继续检查；普通Bar仍按其原滑点规则执行。不能只因时钟是09:30就将普通Bar自动免滑点。
- 竞价成交是额外机会，不消耗多腿组合的三个共同连续交易Bar重试次数；未完成余量进入后续允许时点。竞价与普通Bar可在不同标的的同一Frame共存，同标的同Frame禁止两种来源重复撮合。
- 日终结算仍由独立settlements提供，竞价价格不替代结算价。
- `ifind_auction.index_futures_auction`要求显式日线交易日期、日线开盘价和09:30观察精确匹配，返回标准Auction；供应商字段留在适配层。未修改历史观察快照。

固定快照全量核对23720个合约交易日的09:30记录，全部与日线open精确相等、无缺失或重复，报告`outputs/index_futures_auction_audit.json`。这些检查确认该批实际观察的价格对应关系；其他分钟结束标签、量额单位和32个供应商合约日差异仍分别保留。

## 当前能力与剩余验收

|回测层能力|状态|
|---|---|
|竞价零滑点、普通分钟滑点、指令时间防回填|通用引擎回归通过|
|只读账户/成交观察、外部回调与离线指令|已有接口；竞价在通用runner中可由JSON输入|
|费用、数量/流动性限制、部分成交和组合重试|已有回归，新增竞价约束和重试时钟案例|
|隔夜结算、基准重置、平仓无重复收益|已有真实分钟核对，新增竞价平昨仓回归|
|PnL、现金权益、品种/合约归因|真实股指期货分钟负载独立核对通过|
|统一历史Provider和独立交易日历Frame调度|尚需从研究入口中的读取/调度整理成通用能力|
|各资产、跨市场/夜盘、多腿真实分钟验收|尚未全部完成；策略内置不是条件|
|历史交易状态、费用/保证金、公司行为及PIT资料装配|仍需按原V1范围逐项完成，不能用当前估计值代替|
|大规模性能|现有负载不等于全市场性能验收|
